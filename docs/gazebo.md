# Управление Gazebo через ROS 2

Схема: пульт → TCP/UDP → шлюз → локальный UDP-мост → ROS 2 → Gazebo.
Поддерживаются дифференциальное движение (`geometry_msgs/msg/Twist`),
одометрия (`nav_msgs/msg/Odometry`) и программная аварийная остановка.
Свет, гудок и манипулятор пока не поддерживаются.

## На Linux с роботом

Запустите свою модель Gazebo. Она должна принимать ROS-топик `/cmd_vel`
типа Twist и публиковать `/odom` типа Odometry. Если модель использует
Gazebo Transport, настройте ros_gz_bridge, например:

```bash
ros2 run ros_gz_bridge parameter_bridge \
  '/cmd_vel@geometry_msgs/msg/Twist]gz.msgs.Twist' \
  '/odom@nav_msgs/msg/Odometry[gz.msgs.Odometry'
```

Имена должны совпадать с топиками модели; при необходимости используйте remapping.
Если модель уже предоставляет ROS-топики через ros2_control, этот мост не нужен.
Контроллеры, принимающие TwistStamped, пока требуют преобразования в Twist
либо настройки входа Twist.

В терминале с активированным окружением ROS 2 запустите из корня проекта:

```bash
python3 tools/gazebo_bridge.py --cmd-topic /cmd_vel --odom-topic /odom
```

Используйте системный Python ROS, не Python из uv. ROS-зависимости:
`rclpy`, `geometry_msgs`, `nav_msgs`. Мост слушает только localhost:7447.
В отдельном терминале запустите шлюз (Python 3.14 через uv):

```bash
uv run switchy-op gateway --backend gazebo --host 0.0.0.0 --key your-key
```

Конфигурация `robots/gazebo.yaml` выбирается автоматически. Обычный запуск
без `--backend gazebo` по-прежнему использует встроенный симулятор.

## На пульте

```bash
uv run --extra ui switchy-op client --host LINUX_IP --key your-key
```

Разрешите доступ к Linux по TCP 7000 и UDP 7001. Для Switch укажите этот IP
и тот же ключ в профиле, затем экспортируйте его по инструкции native/README.md.
Движение требует удержания Space/ZR. M/Minus включает аварийную остановку;
в текущем профиле сброса нет — перезапустите шлюз после устранения причины.

## Проверка

1. Проверьте `ros2 topic info /cmd_vel` и `ros2 topic hz /odom`.
2. Запустите мост и шлюз, подключите пульт. Положение и скорость должны
   приходить из одометрии, а не из расчёта команд.
3. Удерживайте разрешение движения, затем отпустите: команда должна стать нулевой.
4. Проверьте аварийную остановку и разрыв сети пульта: шлюз обнуляет движение
   после 400 мс без команд.
5. Завершите шлюз: мост самостоятельно обнуляет команду после 400 мс.
6. Остановите одометрию: через 500 мс мост запрещает движение.

Шлюз также запрещает движение без свежего ответа моста (500 мс).
После восстановления одометрии движение может возобновиться, если пульт
продолжает удерживать разрешение. При аварийном завершении самого ROS-моста
последняя команда может остаться у контроллера: настройте его собственный
тайм-аут команд и проверьте это отдельно.

Этот режим подготовлен для проверки на Linux; реальный запуск ROS/Gazebo
в среде разработки Windows не выполнялся.

Форматы и направления ros_gz_bridge описаны в
[официальной документации](https://github.com/gazebosim/ros_gz/blob/ros2/ros_gz_bridge/README.md).

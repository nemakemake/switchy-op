# Загрузка профилей управления по Wi-Fi (Switch 0.4.0)

Консоль получает конфиги с компьютера, проверяет их и сохраняет на SD без
перестановки карты. Профили можно менять между подключениями к роботу.

## На компьютере

Из корня проекта запустите:

```powershell
uv run switchy-op serve-profiles --directory profiles --key my-download-key
```

Сервер по умолчанию слушает TCP 7080 на всех сетевых интерфейсах.
Другой адрес/порт задаются через `--host` и `--port`.
Разрешите входящий TCP 7080 в брандмауэре компьютера для вашей локальной сети.
Switch и компьютер должны иметь сетевой доступ друг к другу; Wi-Fi с изоляцией
клиентов может его блокировать. IP компьютера на Windows можно посмотреть через `ipconfig`.

В папку положите профили управления `.yaml`, `.yml` или `.json` того же формата,
что `profiles/gamepad.yaml`. Предварительный `export-profile` не требуется:
сервер проверяет YAML/JSON и отдаёт нормализованный JSON для нативного клиента.
Неверные конфиги, `video.json`, файлы больше 32 КиБ и ссылки за пределы папки
не попадают в каталог. Показывается до 32 валидных файлов по имени.
Удобнее использовать короткие латинские имена, например `rover.yaml`.

Сервер перечитывает файлы при запросах: можно менять раскладку на компьютере,
затем обновлять список и повторно загружать её без перезапуска сервера.

## На Switch

1. Откройте менеджер подключений. Из управления роботом — удерживайте **L+R**,
   затем отпустите кнопки.
2. Нажмите **L** — загрузка профилей с ПК.
3. Введите IP компьютера, порт `7080` и ключ `my-download-key`, заданный на ПК.
4. Выберите файл крестовиной. **X** обновляет список, **A** загружает профиль.
5. Проверьте оси, deadman и количество действий. **A** сохраняет и применяет,
   **B** отменяет. На экране списка **B** возвращает в менеджер.
6. Выберите подключение к роботу и нажмите **A**. Новая раскладка уже действует.

Если `profile.json` отсутствует или повреждён, на стартовом экране нажмите **Y**:
тот же загрузчик позволяет установить первый профиль по Wi-Fi.

При применении предыдущий `switch/switchy-op/profile.json` сохраняется как
`profile.json.bak`, новый записывается через временный файл и замену после
успешной записи. На Switch старый файл дополнительно перемещается в
`profile.json.rollback` на время замены: если питание пропадёт между переименованиями,
он восстанавливается при следующем запуске. При неверном ключе, повреждённом ответе или ошибке сохранения
активный профиль не меняется. Если профиль уже существовал, резервная копия
содержит предыдущую версию; при первом скачивании копировать ещё нечего.

Новый файл сохраняется на SD и загружается при следующем запуске приложения.
Менеджер `connections.json` не меняется: адреса и ключи существующих подключений
к роботам сохраняются, даже если секция `robot` скачанного профиля отличается.
При первой установке без списка подключений начальная запись создаётся из
секции `robot` скачанного профиля. Настройки видео не загружаются этим способом.

Адрес ПК и порт запоминаются в `profile-source.json` на SD. Ключ скачивания
в этом файле не хранится; при следующем открытии поля ключа начальным значением
будет ключ из текущего профиля робота. Ключ скачивания может отличаться от ключа шлюза.

## Поведение и ограничения

Загрузка выполняется только без активного подключения к роботу. Профиль никогда
не меняется во время езды; после подключения нужно отпустить кнопки перед
началом управления, как и раньше.

На время одного сетевого запроса меню может ждать: подключение ограничено
примерно тремя секундами на IPv4-адрес, дальнейший обмен — пятью секундами.
DNS для имени хоста может занять дополнительное время; IP удобнее для первого запуска.
Отмена доступна между запросами и на экране подтверждения.

Запросы и ответы защищены HMAC-SHA256 с новым случайным challenge на каждое
соединение. Неверный ключ и изменённый ответ отклоняются. Передача не шифруется;
профиль, включая его секцию `robot`, передаётся открытым текстом. Сервис рассчитан
на локальную сеть. В приложение не добавляется доступ к произвольным файлам ПК.

На ПК проверены настоящий обмен Python-сервера с C++-клиентом, неверный ключ,
подмена подписи, ошибочные файлы, ограничение путей, первая установка,
повторное обновление с резервной копией и отказ записи. Отдельно проверяется
эмуляция запрета перезаписи при переименовании, как в файловом API Switch,
и восстановление после незавершённой замены. Сборка Switch проверяется
devkitPro; меню, клавиатуру и запись на настоящую SD ещё нужно проверить на консоли.

## Проверки разработчика

`native/check_pc.sh` собирает нативный загрузчик и запускает
`native/check_profile_sync.py`, затем штатные проверки управления.
Отдельный запуск после сборки `build/profile_sync_check`:

```bash
uv run python native/check_profile_sync.py -v
```

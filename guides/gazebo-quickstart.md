# Тестовый робот Gazebo: быстрый старт

Цель: управлять готовой машинкой в Gazebo нашим пультом и проверить остановку
при потере связи. Модель дорабатывать не нужно.

Схема: **пульт → шлюз на Linux → наш ROS-мост → ROS 2 → Gazebo**.
Поддерживаются движение, одометрия и программная аварийная остановка.
Свет, гудок и манипулятор в этом режиме пока не подключены.

## 1. Подготовить Linux

Для переключения с Windows используйте свежую копию в домашней папке Linux:
Windows-каталог `.venv` переносить нельзя.

```bash
git clone https://github.com/nemakemake/switchy-op.git ~/switchy-op
cd ~/switchy-op
```

Если копия на Linux уже есть, выполните `git pull --ff-only` в ней.

Рекомендуемая среда: Ubuntu 24.04, ROS 2 Jazzy, Gazebo Harmonic.
Установите ROS 2 по [официальной инструкции](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html),
включая настройку apt-репозитория. Затем установите готовые примеры:

```bash
sudo apt update
sudo apt install ros-jazzy-ros-gz ros-jazzy-ros-gz-sim-demos
source /opt/ros/jazzy/setup.bash
```

Скопируйте или клонируйте этот проект на Linux. Установите
[uv](https://docs.astral.sh/uv/getting-started/installation/), перейдите в корень
проекта и выполните:

```bash
uv sync --frozen
uv run python tools/check_gazebo_transport.py
```

uv подготовит Python 3.14 для шлюза. ROS-мост запускается отдельно системным
`python3` из окружения ROS, без активации `.venv` проекта.

## 2. Запустить машинку — терминал №1

```bash
source /opt/ros/jazzy/setup.bash
ros2 launch ros_gz_sim_demos diff_drive.launch.py rviz:=false
```

Откроется сцена с машинками. Управлять будем синей — `vehicle_blue`.
Если симуляция на паузе, нажмите Play. Launch уже поднимает мост Gazebo ↔ ROS;
дополнительный `parameter_bridge` запускать не нужно.

## 3. Запустить наш ROS-мост — терминал №2

Из корня проекта на том же Linux-компьютере:

```bash
source /opt/ros/jazzy/setup.bash
python3 tools/gazebo_bridge.py \
  --cmd-topic /model/vehicle_blue/cmd_vel \
  --odom-topic /model/vehicle_blue/odometry
```

Мост принимает команды от шлюза на localhost:7447, публикует Twist и читает
Odometry. ROS 2 не требуется устанавливать на компьютер пульта.

## 4. Запустить шлюз — терминал №3

Из корня проекта на Linux:

```bash
uv run switchy-op gateway --backend gazebo --host 0.0.0.0 --key test-key
```

Автоматически используется `robots/gazebo.yaml`. Для подключения с другого
компьютера разрешите входящие TCP 7000 и UDP 7001 в локальной сети.

## 5. Подключить пульт

### Switch

Перед перезагрузкой в Linux обновите `.nro` на SD до 0.5.1. Положите
`profiles/video-disabled.json` на SD как `switch/switchy-op/video.json`:
в тестовом примере камеры нет, а по умолчанию видео требуется для движения.
Это возвращает текстовый экран и снимает только блокировку по видео.

На Linux дополнительно запустите:

```bash
uv run switchy-op serve-profiles --directory profiles --key test-key
hostname -I
```

На стартовом экране Switch нажмите **B**, если предлагается старый быстрый старт.
В менеджере нажмите **L**, введите IP Linux, порт **7080**, ключ **test-key**;
загрузите `gazebo.yaml` и подтвердите **A**. Затем добавьте или отредактируйте
подключение: **IP Linux, TCP 7000, ключ test-key**. Скачивание профиля не меняет
адреса уже сохранённых подключений. Отпустите кнопки после подключения и удерживайте ZR.
Разрешите на Linux TCP 7000/7080 и UDP 7001, если включён брандмауэр.

### Окно на ПК

На компьютере с копией проекта, из его корня:

```bash
uv run --extra ui switchy-op client --profile profiles/gazebo.yaml --host LINUX_IP --key test-key
```

Замените `LINUX_IP` на адрес Linux-компьютера. Если всё работает на одной
машине, используйте `127.0.0.1`. Ключ должен совпадать с ключом шлюза.

| Ввод | Действие |
|---|---|
| Space / ZR (удерживать) | Разрешить движение |
| W / S | Вперёд / назад |
| A / D | Поворот |
| Левый / правый стик | Движение / поворот |
| M / Minus | Аварийная остановка |
| Esc | Закрыть пульт на ПК |

После аварийной остановки отпустите органы управления и перезапустите шлюз:
в текущем профиле кнопки сброса нет. Для Switch настройте IP и ключ в профиле
по [инструкции нативного клиента](../native/README.md).

## 6. Проверить работу

1. Удерживайте Space и нажмите W: синяя машинка должна поехать.
2. Отпустите Space: движение должно остановиться.
3. Проверьте поворот и изменение скорости/курса в окне пульта.
4. Закройте пульт во время движения: машинка должна остановиться.
5. Переподключитесь и проверьте M: движение блокируется до перезапуска шлюза.
6. После перезапуска проверьте завершение шлюза во время движения:
   ROS-мост должен обнулить команду через 400 мс без новых команд.

При отсутствии свежей одометрии мост запрещает движение через 500 мс.
После восстановления данных движение может возобновиться, если разрешение
на пульте всё ещё удерживается. Остановка самого ROS-моста требует отдельного
тайм-аута в контроллере модели: мост уже не сможет отправить нулевую команду.

## Если не едет

В терминале с окружением ROS проверьте:

```bash
ros2 topic info /model/vehicle_blue/cmd_vel
ros2 topic hz /model/vehicle_blue/odometry
```

- Нет одометрии: проверьте Play в Gazebo и запуск примера.
- Нет подключения пульта: проверьте IP, ключ, TCP 7000 и UDP 7001.
- Подключение есть, движения нет: удерживайте Space/ZR, проверьте аварийную
  остановку и правильность обоих топиков в команде ROS-моста.
- Ошибка импорта `rclpy`: выполните `source /opt/ros/jazzy/setup.bash`
  и запускайте мост системным Python, а не через `uv run`.

Сценарий подготовлен по [официальному примеру Jazzy](https://github.com/gazebosim/ros_gz/tree/jazzy/ros_gz_sim_demos).
Полный запуск на Linux/Gazebo в текущей среде разработки не выполнялся.
Подробнее об адаптере: [docs/gazebo.md](../docs/gazebo.md).
